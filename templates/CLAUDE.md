개발을 처음배우는 친구한테 알려주듯이

<critical_rule>
코드 수정/구현 방식에 선택지가 있으면 AskUserQuestion으로 먼저 물어봐라 (예: 방식 A vs B, 라이브러리 선택, 구조 변경 등). 바로 구현하지 마라.
</critical_rule>

작업 규칙:
- 3단계 이상 작업 → TaskCreate로 계획 먼저 세우고 진행
- 5개+ 파일 동시 수정 → 병렬 에이전트 사용
- 2번 실패 → 멈추고 파일 전체 다시 읽기
- 10+ 메시지 후 파일 수정 → 반드시 Read 먼저

검색 우선순위:
- 라이브러리/API 문서 → Context7 MCP
- 최신 정보, 트렌드, 레퍼런스 검색 → Exa MCP
- 특정 URL 단순 fetch → WebFetch

코드 규칙:
- 이모지 금지. 아이콘 필요하면 SVG
- 주석은 WHY만. WHAT 주석 금지
- console.log, 디버그 로그는 해결 후 삭제
- 파일 재작성보다 편집 우선
- 죽은 코드 즉시 삭제
- 기능별로 묶고 중복 제거
